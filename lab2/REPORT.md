## Часть 2 — Метрики (Prometheus + Grafana)

Для начала создали в корне проекта файл prometheus.yml - конфиг для prometheus. Настроен он был так, что каждые 5 секунд Делает GET запрос на эндпоинт /metrics. Ответ парсится и сохраняется в БД.

![[Конфиг для Prometheus.png]](.photos/Конфиг для Prometheus.png)

Затем также создали promtail-config.yml - конфиг для promtail. Для начала прописали так, чтобы Promtail работал как веб-сервер (оказывается у него есть встроенный веб-сервер), который слушает порт 9080 внутри контейнера. Гпт сказал выключить протокол gRPC потому что он в лабе не нужен (кто я такой чтобы спорить с роботами, им еще мир захватывать). Затем был указан файл positions.yaml, что нужно для того чтобы промтейл туда мог записать закладку последней позиции чтения, то есть последний байт логов контейнера который он читал. В клиентах указали loki, потому что ему он будет все отправлять.
Блок **scrape_configs** нужен для того чтобы прописать как именно промтейл будет собирать логи. Указали метку задачи "docker", docker_sd (service discovery) - механизм автообнаружения сервисов, который в нашем случае опрашивает сокет докера. Интервал обновления для именно этого мероприяти поставили 5 секунд.
Блок **relable_configs** - для преобразования меток. Указали метку источника "__meta_docker_container_name" и так там будет автоматически ставиться метка контейнера. Также назначили метку цели и в рещультате в логах будет: container="/lab2-app"

![[Promtail конфиг.png]] (.photos/Promtail конфиг.png)

После этого написали docker-compose.yml. В сервисах:
1. **app** (наш микросервис, пробрасывается через порт 8000)
2. **prometheus** - собственно сервис для prometheus. Используем докер-образ prom/prometheus из Docker Hub. Используем порт 9090. Также монтируются тома, чтобы использовался наш конфиг (при запуске контейнера выполняется команда '--config.file=/etc/prometheus/prometheus.yml').
3. **grafana** - Также используем официальный образ, порт 3001 с локалхоста ведет на 3000 в контейнере чтобы избежать конфликтов. Передаем переменную окружения с паролем от админа (для первого запуска)
4. **loki** - Скачиваем Loki, даем имя, назначаем порт 3100, подключаемся к сети
5. **promtail** - Скачиваем образ Promtail, также как с Grafana используем кастомный конфиг. Монтируем системный файл docker.sock в контейнер для того чтобы Promtail мог видеть все запущенные контейнеры и находить их логи. 
Все контейнеры в одной сети - "monitoring".

![[Docker-compose конфиг.png]](.photos/Docker-compose конфиг.png)

Далее docker-compose up и проверка работы контейнеров.

![[Проверка состояния контейнеров.png]](.photos/Проверка состояния контейнеров.png)

Теперь в браузере заходим по адресу 0.0.0.0/3001, логинимся через admin и через графический интерфейс Grafana создаем новый дашборд. Добавляем контейнер с Prometheus как источник данных.

![[новый Data Source.png]](.photos/новый Data Source.png)

В новом дашборде добавляем график RPS. На языке PromQL строка `sum(rate(http_requests_total[1m]))`  берет метрику количества http запросов (только в последнюю минуту), вычисляет среднее посекундное увеличение счетчика за указанный интервал и складывает все в сумму. Таким образом считаем RPS.

![[График RPS в Grafana.png]](.photos/График RPS в Grafana.png)

Следующий график - процент ошибок среди всех http запросов за последнюю минуту.

И последний график - 95ый квантиль длительности http запросов за последнюю минуту.
